StegSolve：人肉翻位平面

StegSolve-1.4.jar 是老牌 Java 工具，界面简陋但不可替代——它能把每个颜色通道的每个位平面单独显示成图，肉眼直接看到藏进去的内容。

启动方式（双击没反应就用命令行）：

java -jar StegSolve-1.4.jar

核心操作只有两个：

  1. File → Open 载入图片，点 Next / Prev 按钮在 0-7 共 8 个位平面之间循环切换；
  2. 重点看 Red plane 0 / Green plane 0 / Blue plane 0（最低位平面），LSB 隐写的文字、图案通常直接浮现在这里。

其他常用视图：Colour → Alpha 看透明度通道（PNG 的 alpha 里藏字很常见）、Static 模式对比相邻平面差异。翻到某一平面出现黑白噪点里的清晰轮廓或文字，基本就中了。

StegSolve 的不可替代场景：flag 是"画"在位平面里的图案而不是一串字节——zsteg 只会报差异，人眼才能读出图案。

zsteg：一条命令自动检测

zsteg 是 Ruby 写的 LSB 隐写自动扫描器，对 PNG 和 BMP 命中率很高。Windows 下需要先装 Ruby 环境（用 RailsInstaller，见压缩包那篇），然后：

gem install zsteg

:: 全量扫描，常用
zsteg -a secret.png

:: 只看指定数据流，比如 B,G,0 表示蓝通道最低位
zsteg -a -v secret.png
zsteg secret.png -1 b,g,0

:: 反过来，用 zsteg 往图里藏东西做自测
zsteg embed1 flag.png "test hidden"

输出里出现 Imagedata found after image data 说明尾部有附加数据；出现 hidden in channel 则直接给出 LSB 提取出的内容。建议 -a 全扫，跑几秒换全覆盖。

GIF 多帧隐写

GIF 隐写考的是帧：把 flag 的每一帧拆开，或者在帧间塞额外数据。流程：

  1. 用 gifsicle 或 010 Editor 看帧数，异常多帧就是信号；
  2. 拆帧：gifsicle flag.gif --unoptimize -S 1 > f.gif 逐帧导出，或用在线 GIF 浏览器左右翻帧；
  3. 帧内容拼字：每帧显示一个字符，按顺序读；
  4. 帧延时藏信息：帧间隔 83ms、125ms 之类的"奇怪延时"，把延时值转 ASCII 常能拼出 flag。

二维码题的四种花样

qr 工具目录（我用的解码核心是 zbar / zxing + 脚本）应对以下几类：

1. 标准解码失败

先做图像预处理再解：放大 4 倍、二值化、反色、旋转。Python 一行流：

from pyzbar.pyzbar import decode
from PIL import Image
print(decode(Image.open("qr.png")))

2. 残缺二维码

三个定位角至少剩两个才有救。手工补黑块时记住：二维码纠错等级最高 30%，小面积缺失直接补纯色块就可能解出；大面积缺失要按数据区规律推。

3. 彩色二维码

颜色本身是信息：把每种颜色映射成 0/1（通常深色=1）重绘成标准黑白码再扫。先统计颜色种类，两种以上颜色基本就是这个套路。

4. 多帧/变形 QR

GIF 里的 QR 要逐帧解再拼接内容；"眼睛在动"的动图 QR 同理。
